# チュートリアル: ミニブログを作る

このチュートリアルシリーズでは、空のディレクトリから、小さいながらも本物のブログアプリケーションを作り上げます。進め方は Guren 流そのもの: **ジェネレーターで生成し、生成されたコードを読んで理解し、`check` と `audit` で機械的に検証する** — という開発ループを、機能を足すたびに回します。完走する頃には、Guren アプリの各パーツがどう噛み合うのかと、日々の開発フローの両方が身についているはずです。

途中で見慣れない用語が出てきたら [用語集](../guides/glossary.md) を参照してください。

## 作るもの

訪問者が次のことをできるミニブログです。

- ページネーション付きの投稿一覧を眺め、各投稿を読む
- ユーザーアカウントでサインインする
- 投稿を書く・編集する・削除する（サインイン済みユーザーのみ）。各投稿には著者が表示される
- 投稿にコメントを残す

さらに、完成したアプリのコード、生成スペック、アーキテクチャ上の意思決定を Docs Graph で結び付けます。

## シリーズ構成

各パートは前のパートの続きから始まる積み上げ式です。順番どおりに進めてください。

1. **[ブログ投稿アプリを作る](./create-blog-post-app.md)** — 新規アプリを雛形生成し、`bunx guren add resource` の 1 コマンドで投稿の CRUD 一式（スキーマ、モデル、バリデーター、リソース、コントローラー、ルート、4 つの React ページ）を生成します。その後、`guren context` とスペックビューで全体像を導出してから生成コードをレイヤーごとに読み解き、バリデーションメッセージや `fillable` で磨き、`guren check` と `guren audit` で検証します。**最終成果:** コードを 1 行も手書きせずに CRUD が動き、その全レイヤーを説明できるところまで。
2. **[認証を追加する](./authentication.md)** — コマンド 1 つで認証スタック（ログイン・登録・パスワードリセット）をインストールし、デモユーザーでサインインし、投稿の変更をログイン必須にして、すべての投稿に著者を紐づけ、スキーマ変更で古くなったスペックビューを `check --spec` のドリフトゲートで追随させます。**最終成果:** サインイン済みユーザーだけが投稿を変更でき、各投稿に書いた人が表示され、Part 1 で `audit` が指摘した警告が解消されて静かになるところまで。
3. **[リレーションシップ: コメント](./relationships.md)** — 投稿とユーザーの両方に関連する `comments` テーブルを追加し、単機能の `make:*` ジェネレーターで骨組みを作って、`hasMany` / `belongsTo` のリレーションシップと投稿ページのコメントフォームを仕上げます。その後、スペックビューを生成し、アーキテクチャ上の意思決定を記録し、リンクを検証して、完成したシステムを Docs Graph で確認します。**最終成果:** サインイン済みユーザーがどの投稿にもコメントでき、その動作を支えるコード、生成ビュー、意思決定が結び付いた状態まで。

## 前提条件

- **[Bun](https://bun.sh) 1.1 以降** — 必須なのはこれだけです。
- 以上です。雛形生成のデフォルトは **SQLite** なので設定は一切不要 — Docker もデータベースサーバーも要りません。（雛形生成時に PostgreSQL や MySQL も選べますが、このコースではデフォルトの SQLite のまま進めます。）

各パートの所要時間はおよそ 15〜25 分です。

> [!TIP]
> このシリーズは機能を作ることに集中しています。環境セットアップ、レンダリングモード、本番ビルドまで含めた幅広いツアーは [はじめる](../guides/getting-started.md) と [ファーストステップ](../guides/first-steps.md) を、コマンドの全体像は [CLI リファレンス](../guides/cli.md) を参照してください。

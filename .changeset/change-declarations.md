'@guren/cli': minor
---

`guren change:lane` and `guren change:evidence` now lower a fact an approved, open plan declares (RFC 0040 §3). An added source file that `plan:scaffold` writes for an element the plan adds is `low` when it is at that path and exports what the scaffold's own output exports; a policy's provider must be the one the scaffold writes, a policy or controller file must hold nothing but imports, types and the class, which extends the base the scaffold imports and has no member but the planned abilities or actions. An added table of a model the plan adds is `low` when its statement is the one the scaffold writes into that schema, columns, defaults, keys and indexes included. The report names the plan and the element (`declared by docs/plans/comments/plan.json#model.comment`), and `record.json` carries it as `declaredBy`. Nothing is declared in a change that writes a plan record, and a file or table a second open plan also claims stays where it was.

A declared table's own `sql` default and index callback are the scaffold's, so they no longer keep `db/schema.ts` at `medium`. An added migration is `low` when it does nothing but create the tables the plan adds, in the statements drizzle-kit writes, read whole and as drizzle's migrator cuts it at `--> statement-breakpoint` (each `CREATE TABLE` with exactly the planned columns, each with the type, nullability, keys and default the scaffold's builders give it, and every planned unique, index and foreign key stated once, after its table, and nothing else), its folder holds `migration.sql` and `snapshot.json` and nothing else, and the snapshot is the previous migration's plus what the SQL creates.

Once both sides' security records are compared, each route is a fact of its own: `route-added`, `route-removed`, `route-changed` and `agent-tool`, each `medium`. An added route is `low` when the plan adds it in the project root and its record holds what the plan states: method, path and name, the planned controller action, the planned middleware by name, bindings by model file and export, agent metadata, each contract as the planned validator's export with the planned keys, types and rules, and an awaited `authorize()` statement of the planned policy ability on the policy's model, imported under its own name. A route reusing another route's name is not declared. A route is not declared while a route registered after it that the change does not add, of its method or `ALL`, has a path some request could match too. The routes file `plan:scaffold` writes is `low` when it is what the scaffold writes against the head's model and validator files, and the routes entry's edit no longer keeps the change at `medium` when it is exactly what `plan:scaffold --mount` writes, the mounted file is still the scaffold's, and every route fact is a declared addition of that file's routes, each once, unless the mounted file sets an alias another route uses that the entry does not set after it. The security records now carry each route's bindings and `.agent()` metadata, and their version moves to 2. A table whose builders come from both a `drizzle-orm` subpath and the `@guren/orm` barrel of the same dialect, as `appendTableToSchema()` writes into such a schema, is now declared as well. Listing a declared table in an object of tables no longer keeps `db/schema.ts` at `medium`, and dropping a table from such an object now does.

An edit to the application entry that only adds names to the `providers` and `config` arrays of its `createApp()` literal, with the imports binding them, is now a `provider-added` or `config-added` fact per entry, `medium`, rather than `source-edited`. The call must be the `createApp` imported from `@guren/core`, made at the top level. Anything else in the file keeps it `source-edited`, and so does a literal holding a spread, a computed key or `__proto__`, a method or accessor named after a list, or an added import of a name the rest of the file reads. The provider a planned policy implies is `low` when the entry is exactly what `plan:scaffold` writes for that scaffold step's providers and the provider and its policy hold what the plan declares, so a scaffold step's commit no longer stays `medium` for its registration. No declared file is `low` while a file of the same name with another extension sits beside it at the head: the scaffold imports `./P.js`, and Bun runs a `P.js` in place of `P.ts`.

A changed or removed route, any other migration, an altered table, a removed file, a file a plan's `commands` write, a config entry, and an edit to a file an earlier task of the plan added stay `medium` for now.

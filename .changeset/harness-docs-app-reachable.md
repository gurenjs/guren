The agent harness `guren agent:init` installs now describes what an app can reach. The controllers rule says which Inertia props are shared (flashed `errors`, `_i18n`, and `auth.user` only where `app/Providers/AuthProvider.ts` exists) instead of claiming a fresh app shares none, and says a provider that only registers a policy in `boot()` still declares `register(): void {}`, since `ServiceProvider` leaves it abstract and a boot-only provider did not compile. The API digest `guren context` prints, the `guren guidelines` policy line and the `make:feature --policy` next step say the same. The `guren-api` skill points each subsystem at its guide on guren.dev and the installed declarations rather than at framework source paths no app has, with short signatures for jobs, mail and events. New entries cover `useRouteForm()` with route `params` and a shared form typed as `RouteForm<…>`, `Model.inTransaction(trx)` beside `transaction()`, `authorize(ability, [Model, context])` with a plain object, async policy abilities and `denyAsNotFound()` (and the wider return type the `: boolean` stubs need), and reading what a faked mail sent with `sent()` / `sentTo()`. The testing rule no longer assumes every app's `User` model hashes `password`. Run `bunx guren agent:sync` to pick them up.

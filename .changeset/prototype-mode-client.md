**Prototype mode (RFC 0021 Part 1)** — `@guren/inertia-client/prototype` answers Inertia visits from a fixture module in the browser, through Inertia 3's public `HttpClient` interface, so a build of the real page components runs with no server. `definePrototype({ manifest, shared, state, routes })` types each handler's `params` from the manifest path, its `body` from `apiRoutes<ApiRoutes>()`, and `page(contract, props)` against the same `PageProps<>` a controller is checked against. Handlers answer with `page()`, `redirect()`, `errors()`, `location()` or `notFound()`; redirects are followed in place, validation errors re-render the page the visit came from, partial reloads return only the requested props, and the public `http.onRequest` / `onResponse` / `onError` handlers and `AbortSignal` cancellation behave as with the built-in XHR client. State persists in `sessionStorage` (or `localStorage`, or not at all) and `?prototype.reset=1` discards it. `startInertiaClient({ prototype })` wires it in; behind `import.meta.env.GUREN_PROTOTYPE` the branch is dead code in the production bundle. `hono` becomes a peer dependency: the client matches URLs with Hono's own router, so every path syntax the server routes also resolves in the prototype.

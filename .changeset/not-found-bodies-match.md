Outside debug, the exception handler replaces a 404 message the framework composed from the record with `Not Found`: the one `findOrFail()` and route model binding throw (`Project not found for id=99999`), the ones `NotFoundHttpException.forModel()`, `forRoute()` and `forResource()` write, and a 404 thrown with no message. `denyAsNotFound()` and `abort(404)` now default to that same `Not Found` (they said `Not found.` and `Error`), so with the framework's defaults a record a policy hides gives a body byte-identical to one that does not exist, for JSON, XHR and Inertia callers and for a browser's 404 page. The message used to tell the two apart, which is what `denyAsNotFound()` is for. Only the framework's own construction counts: a message a developer wrote (`abort(404, '…')`, `denyAsNotFound('…')`, `HttpException.notFound('…')`, `new NotFoundHttpException('…', 'Invitation', id)`) is still shown as written, and so is an app error that carries its own `resourceType` or `modelName` field. Only the top-level `message` of the body an exception's `toResponse()` builds is replaced, and only while it is the exception's own, so a message `toResponse()` writes itself is kept. The exception is never modified: the detailed message stays on it for reporters, logs and debug responses. A policy's 404 denial now throws a `NotFoundHttpException` (still an `HttpException`), so a renderer registered for `NotFoundHttpException` renders hidden records as well as missing ones. A test asserting the old 404 text outside debug needs the new one.

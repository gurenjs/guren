Approving a plan now settles, once, the elements no behaviour can reach: commands, added or altered side effects, and altered columns. `plan:render` pins them to the page as an advisory **Completes without a behaviour** warning (the Dev Center's review serves that page, and its approve check lists them too), and `plan:approve` prints them, `--dry-run` included, and records them in the approval entry as `acceptedWithoutBehaviour`, outside the plan hash. Where only a behaviour could otherwise have lifted such an element, it is lifted once its step has a verified run that still holds and it is at its completion state: `plan:status` reports it in the new `accepted` state (an altered column whose change its properties show still reads `verified`), and `plan:close` and `plan:next` count it as complete, so these elements no longer need a `plan:waive` each before a plan closes. Nothing changes about what counts as `verified`, and an accepted element that is below its completion state, or whose fingerprinted files changed, is held exactly as before. The acceptance belongs to the approved hash: a revision accepts again at its own approval. A plan approved before this release gets the acceptance by running `plan:approve` on it again, which records it in the existing entry. `plan:close` lists accepted elements under the plan document's Decisions and in its `--json` report (`accepted`), and offers no `make:adr` for them.

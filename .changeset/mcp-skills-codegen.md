`guren codegen` publishes an app's MCP skills, and `guren make:mcp-skill` scaffolds one (RFC 0042 §1). A skill is a directory holding a `SKILL.md` under `resources/skills/`, or under `modules/<name>/resources/skills/` for a module, whose name becomes the skill's path prefix. Codegen writes `.guren/mcp-skills.gen.ts`, the `{ files, binary }` module that `mcpPlugin({ skills: { files: () => import('@/.guren/mcp-skills.gen') } })` serves: every regular file below a skill's directory, UTF-8 files as text and any other as base64. Dotfiles, dot directories, symlinks (the skills directory's own included) and directories that hold no `SKILL.md` are left out. Codegen warns about a manifest spelled in another case and about a `SKILL.md` below another skill's directory, which the endpoint refuses at boot. The module is written for an app that has a skill or whose source names the module, and is rewritten empty, never removed, after the last skill goes, so the configured `import()` resolves on a fresh checkout too. The Vite plugin regenerates it when a file under a skills directory changes. `make:mcp-skill <name> [--description <text>] [--module <name>]` writes the `SKILL.md` with its frontmatter quoted, refuses a name outside the Agent Skills rule (1 to 64 lowercase letters and digits, single hyphens between them), and prints the `skills` option to add when the app's `mcpPlugin()` calls, read whole, carry none. A scaffolded markdown file under `resources/` no longer installs the UI token stylesheet for naming a token class in prose. The MCP Skills guide documents both commands, and what every token of the app can read.

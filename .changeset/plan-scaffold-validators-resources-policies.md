`guren plan:scaffold` now also writes a scaffold step's validators, resources and policies (RFC 0030 §5). The validators go in `app/Http/Validators/<Model>Validator.ts`, each field written from its planned type, `required` and rules in the form `plan:status` reads back; a validator an action takes its query or params from coerces numbers and booleans. Each resource of the model the step adds is a `Resource` subclass with the planned payload, copying a field from its column where the column reads back as the planned type and calling a stub that throws otherwise. Each policy of that model denies every ability until its rule is written, and `app/Providers/<Policy>Provider.ts` registers it with the gate, added to `createApp({ providers })`. The report lists the rules and fields it wrote as a stub or not at all, and the provider it registered. New refusals, all before the first write: a validator name another validator file exports, a resource name not ending in `Resource`, an ability named after a `Policy` member, and a provider it cannot register. `make:validator`, `make:resource`, `make:policy` and `make:feature` write through the same templates, with unchanged output.
